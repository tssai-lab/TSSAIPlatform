# 单机交付收口 SOP

目标：甲方在一台 NVIDIA GPU 服务器上自行安装平台，后续可接入更多计算节点。

## 执行规则

1. 先代码、再部署、最后手册；各阶段独立提交和验证。
2. 以当前内网已发布代码为基线，保留外网 CPU 环境隔离；不得静默向外网发布。
3. 删除必须有引用依据；保留已执行数据库迁移、正常测试、实际依赖的旧 API 和 kubectl。
4. 不改变用户资产、权限模型或数据库结构；失败、重复请求、清理与资源隔离是回归重点。
5. 中文注释重点解释职责、事务、幂等与失败行为；不批量翻译生成文件、第三方代码和已执行 SQL。

## 上下文与假设

- A：当前 GPU 基础镜像为固定摘要的 PyTorch 2.7.1/CUDA 12.8；当前推理执行仍使用 CPU 镜像和 kubectl。
- A：现有实验室安装器明确限制双节点和原 Git 仓库，不能直接用于甲方单机 ZIP 交付。
- B：优先交付预构建镜像和可维护源码；不默认要求甲方在完全离线状态重建 Maven/npm/Python 全部依赖。
- A：甲方已确认要求支持 Ubuntu 20.04 LTS 及以上版本。Ubuntu 20.04、22.04、24.04 分别建立依赖与验证记录；后续版本通过兼容性检查后纳入，不把未测试版本标成已验证。
- B：默认目标架构为 x86_64（当前 NVIDIA 5090 工作站链路）；检查内核、cgroup、驱动和运行时，不凭猜测操作磁盘、升级驱动或重启。离线系统包不能跨 Ubuntu 版本混用。

## Ubuntu 支持要求与前置差异

支持目标为 Ubuntu 20.04 LTS 及以上，不代表任意旧内核、任意驱动组合均可运行。20.04、22.04、24.04 及后续版本需分别记录验证状态与离线包来源；不借用一个版本的 deb 包给另一版本安装。

- 当前安装器采用 cgroup v2；Kubernetes 文档要求该模式内核至少 5.8，并要求 kubelet/运行时采用 systemd cgroup 驱动。20.04 需先核对内核和启动配置，涉及重启的准备步骤单列，不自动操作其他服务。[Kubernetes 文档](https://kubernetes.io/docs/concepts/architecture/cgroups/)
- CUDA 12.8.1 文档列出了 Ubuntu 20.04 x86_64 的开发环境组合；这只能支持兼容性调查，不能代替本平台和 RTX 5090 的实机验证。训练镜像已包含用户态 CUDA/PyTorch，宿主机仍需匹配的 NVIDIA 驱动与容器工具。[NVIDIA 文档](https://docs.nvidia.com/cuda/archive/12.8.1/cuda-installation-guide-linux/index.html)
- 不将“CPU 环境启动成功”“4080 训练成功”写成“5090 及所有 Ubuntu 版本均已通过”。
