## 真实依赖保护门

`backend/scripts/qa/container-suites.json` 列出 10 套必须实际执行的 PostgreSQL、MinIO、Redis 测试。脚本保留原断言，独立核对每套 XML：本轮报告、实际用例数、失败、错误、跳过。Maven 显示成功但测试被跳过也会被拒绝。

前提：本机独立 Linux/WSL Docker，无运行中的业务容器；Python 3；已准备 Maven repository 缓存及脚本列出的 6 个固定镜像。本入口不是客户安装器，也不证明某个操作系统已通过交付认证。

```bash
# 在后端仓库执行；目录必须是全新绝对路径，缓存只读复制。
bash backend/scripts/qa/run-container-integration.sh --preflight
TSS_MAVEN_REPOSITORY=/本机缓存/repository \
  bash backend/scripts/qa/run-container-integration.sh /项目证据/新一轮

# 代码交付候选：所有 *Test + 同一套容器报告检查。
TSS_MAVEN_REPOSITORY=/本机缓存/repository \
  bash backend/scripts/qa/run-container-integration.sh /项目证据/全量新一轮 --all

# 测试报告检查器自身的拒绝场景
python3 -B -m unittest discover -s backend/scripts/qa -p 'test_*.py'
```

脚本不拉镜像、不连接远端 Docker；Maven 限 2 CPU / 2 GiB，PostgreSQL/MinIO/Redis 各限 1 CPU / 1 GiB，业务测试端口只绑定本机。Testcontainers 的 Ryuk 清理控制容器使用其默认随机端口，因此整个入口只用于独立本机 Docker。测试不连接平台业务库、不占 GPU。原缓存只读，构建在一次性容器的 Linux 目录执行，退出时导出原始报告；源码快照、XML、日志和镜像身份留在证据目录。正常清理由 Testcontainers 处理，发现本轮标签残留直接失败，不执行批量清理。

报告目录为 `source/backend/target/surefire-reports`，总入口结果为 `maven-exit.txt`、`integration-summary.json`、`remaining-containers.txt`。检查全部测试时也要单独列明真实集群用例的跳过原因，不能把 10 套依赖通过当成真实 GPU 或登录验收。
