# 资源监控模块开发总结

## 概述

为 TSS 平台实现了完整的 K8s 集群资源监控功能。后端自动发现 K8s 节点、定时采集 CPU/内存/GPU 使用率，通过 REST API 提供给前端。已部署到生产环境并验证通过。

## API 端点

所有接口位于 `/api/resource-monitor`，完全匹配前端约定。

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/summary` | 登录用户 | 集群总览（节点数、任务数、平均GPU使用率） |
| GET | `/servers` | 登录用户 | 服务器列表（含实时CPU/内存/GPU使用率） |
| POST | `/servers` | 管理员 | 手动添加服务器 |
| GET | `/servers/{serverIp}` | 登录用户 | 服务器详情（含运行中/排队任务列表） |
| DELETE | `/servers/{serverIp}` | 管理员 | 删除服务器（有运行任务时拒绝） |
| GET | `/servers/{serverIp}/metrics?interval=` | 登录用户 | 资源使用趋势（支持1min/10min/1hour/1day） |
| PUT | `/servers/{serverIp}/queue/reorder` | 管理员 | 排队任务上移/下移 |
| PUT | `/servers/{serverIp}/queue/priority` | 管理员 | 修改排队任务优先级 |
| DELETE | `/servers/{serverIp}/queue/{taskId}` | 管理员 | 取消排队任务 |

## 工作原理

### 节点自动发现

应用启动时自动执行 `kubectl get nodes -o json`，解析每个节点的：
- metadata.name → K8s 节点名
- status.addresses → IP 地址
- status.capacity → CPU 总核数、内存总量
- status.conditions → 在线状态

新节点自动写入 `compute_server` 表，已有节点更新状态和容量。

### 指标定时采集

每 30 秒执行一次：

1. **获取节点容量**：`kubectl get nodes -o json`
2. **获取实时指标**：调用 K8s Metrics API `/apis/metrics.k8s.io/v1beta1/nodes`，解析 CPU 使用量（支持 nanocores `n` 和 millicores `m` 格式）和内存使用量
3. **计算百分比**：CPU使用量 / CPU总核数 × 100，内存使用量 / 内存总量 × 100
4. **采集 GPU**（如果有）：查询 DCGM Exporter 的 Prometheus 端点
5. **写入快照**：更新 `server_metric_snapshot` 表
6. **写入历史**：追加 `server_metric_history` 表
7. **计算状态**：任一指标 ≥ 85% → `warning`，否则 `online`
8. **清理过期数据**：定时删除超过保留期的历史指标

## 部署前提

1. K8s 集群需要部署 **Metrics Server**：`kubectl top nodes` 能正常输出
2. 后端 ServiceAccount 需要 Metrics API 的 RBAC 权限
3. 如需 GPU 监控，需部署 **NVIDIA DCGM Exporter**（DaemonSet）

## 当前生产状态

- 集群：`k8s-master`（3核4G 主节点）+ `k8s-node1`（4核8G 工作节点）
- 部署方式：Docker 容器，GitHub Actions 自动构建推送
- 采集间隔：30 秒
- 指标保留：7 天
