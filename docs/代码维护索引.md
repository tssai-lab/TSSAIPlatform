## 前端训练代码

页面仍可从 `services/platform.ts` 使用原接口；`services/code.ts`、`services/codeV2.ts` 是兼容入口，不应另写一套重复实现。

| 需要修改的内容 | 位置 |
| --- | --- |
| V2 请求及类型 | `services/trainingCode/v2OwnerApi.ts`、`v2AdminApi.ts`、`v2Types.ts` |
| 响应字段兼容、业务错误、文本解析 | `v2Mapping.ts`、`v2Content.ts` |
| 完整目录读取与路径 | `v2Tree.ts` |
| 资产及版本操作、列表汇总 | `assets.ts`、`inventory.ts` |
| 审核及训练准入 | `approval.ts` |
| 版本/草稿预览 | `preview.ts` |
| 本人/管理员草稿操作 | `workspace.ts`、`adminWorkspace.ts` |

依赖方向是页面 → 上层训练代码服务 → V2 协议服务。上层兼容逻辑可使用稳定的 `codeV2.ts` 入口，V2 模块不得反向引入上层 `code.ts` 的运行时代码，避免循环；新增 API 应放对应职责模块，再按需由兼容入口导出。旧 API 兼容仅在明确“不支持端点”时使用，权限错误、网络错误不能被吞掉或自动回退。

## 页面

- 管理员代码资产：`pages/task/trainingCode/adminAssets/index.tsx` 保留表单与写操作编排；`useAdminCodeBrowser.ts` 只处理目录/文件读取、迟到响应隔离；`presentation.tsx` 是展示工具，`versionColumns.tsx` 只接收按钮回调。
- 训练对比：`pages/task/compare/index.tsx` 保留目录和界面；`comparisonModel.tsx` 放指标/分组/显示规则；`useCompareData.ts` 负责一轮对比读取及并发响应隔离。
- 指标：共用 `services/mlflow.ts` 与 `TrainingMetricsPanel`。零值、空结果、请求失败是三种不同状态，不能用同一个空数组表示。

## 改动后的检查

1. 为改变的规则增加故障或边界用例，保留原断言。
2. `npm test -- --test-concurrency=1`；`npx --no-install max setup` 后 `npm run tsc`；`npm run lint:governance`；`npm run build`。
3. 涉及读取交互时，使用 `scripts/qa/read-errors-harness.mjs` 和对应 `*-check.js` 复查失败提示、重试、切换和迟到响应。夹具仅用于隔离测试，不能编入生产入口。
4. 按 `docs/code-governance-sop.md` 区分单元、隔离页面及真实集群证据；改写操作、权限、数据库时需要相应集成测试，不能仅凭只读页面通过就上线。

`verify-code-module-move.mjs` 与其 JSON 是 G2 搬移的历史审计材料，不是要求今后 160 个函数永远不许修改的保护门。

## 三处边界修复维护入口

- `services/trainingCode/approval.ts` 的 `checkCodeVersionForTraining` 调完整准入接口，不能用只检查代码包的 V2 validate 替代，也不自动重放。
- 模型与数据集主详情的读取序号、路由及查询参数校验必须覆盖成功、失败、finally、跳转与卸载；不要只给成功响应加判断。
- `utils/datasetWorkspaceRead.ts` 区分工作区暂时故障与明确不可访问；详情错误重试不得隐含创建、放弃或删除。具体假设、用例和未验证范围见 `three-boundary-fixes-sop.md`。
