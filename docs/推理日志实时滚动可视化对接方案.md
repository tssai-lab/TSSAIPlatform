# 推理日志实时滚动可视化 — 对接方案

给前后端对齐用的约定。日志与结果可视化（`ResultVisual`）分离；系统操作审计日志（`/system/log`）不在此范围。

前端入口：`src/pages/inference/workbench/index.tsx` 结果 Drawer →「运行日志」。

## 一、前端已落地（请按此理解现状）

前端已实现 **内嵌 xterm 终端 + 完整日志展示 + 运行中轮询刷新**，**尚未**对接后端专用增量 / SSE 接口。

| 项 | 当前实现 |
|----|----------|
| UI | xterm.js 内嵌终端（深色、等宽、可滚动）；保留「下载日志 / 刷新 / 复制」 |
| 内容范围 | **展示日志文件全文**（产品要求全部展示；已取消早期 1MB 截断预览） |
| 数据来源 | `logPath` → `objectNameFromMinioPath` → `GET /api/files/download?objectName=` → 文本写入终端 |
| 「实时」做法 | 任务为 `pending \| queued \| scheduled \| running` 时，约每 3s：刷新任务 result（状态 / `logPath`）+ 再下载日志；若内容变长则 **追加增量** 并尽量贴底滚动 |
| 终态 | 停止轮询；终端保留已加载的完整内容 |
| 后端依赖 | **无新接口**；依赖运行中 MinIO 日志可追写可读，否则只能看到已落盘内容 |

相关代码：

|------|------|
| `src/components/inference/InferenceLogPanel/index.tsx` | xterm 终端面板 |
| `src/pages/inference/workbench/index.tsx` | Drawer 挂载；运行中轮询 result |

### 能力边界（需与负责人对齐）

1. **「全部展示」**：指终端内加载并展示存储上的**完整日志文件**（可上翻；`scrollback` 较大）。超大文件可能导致浏览器内存/卡顿，完整文件仍建议保留「下载日志」。
2. **「实时输出」**：当前为 **轮询整文件下载再 diff 追加**，不是 SSE / offset 增量。延迟约数秒；日志仅在任务结束后一次性写入时，运行中不会持续「往外蹦」。
3. 文档后文 **方案 A** 仍是生产级 live 的后端对接目标；当前前端实现接近「方案 B 全文可视 + 过渡期伪实时」。

## 二、方案 A：生产级实时滚动（后端待对接）

目标：运行中可靠跟读，避免反复整包下载。前端 xterm 壳已具备，数据源切换到增量接口即可。

### A.1 后端：增量读接口（关键）

```http
GET /api/inference/tasks/{id}/logs?offset={byteOffset}&limit={maxBytes}
```

| 参数 | 说明 |
|------|------|
| `offset` | 已读字节游标，首次为 `0` |
| `limit` | 单次最大字节数，建议默认 64KB～256KB，并设上限 |

建议响应：

```json
{
  "content": "本次新增的纯文本（UTF-8）",
  "offset": 0,
  "nextOffset": 12345,
  "eof": false,
  "logPath": "minio://users/{uid}/inference-results/{taskId}/xxx.log",
  "status": "running"
}
```

| 字段 | 说明 |
|------|------|
| `content` | `[offset, nextOffset)` 区间的新增文本；无新增时为空串 |
| `offset` | 本次请求使用的起始游标（回显） |
| `nextOffset` | 下次请求应带的游标 |
| `eof` | 任务已终态且当前无更多可读字节时为 `true` |
| `logPath` | 可选；与任务元数据一致 |
| `status` | 可选；便于前端决定是否继续轮询 |

行为约定：

1. **运行中可追写**：worker 将 stdout/stderr **追加**到同一日志对象（或本地文件再同步到 MinIO），保证 offset 语义成立。
2. **`logPath` 未就绪**：返回 `content=""`、`nextOffset=0`、`eof=false`，HTTP 仍 200。
3. **鉴权**：按任务归属校验，与 `GET /inference/tasks/{id}` 一致。
4. **编码**：UTF-8；截断尽量落在字符边界。
5. **终态**：`success | failed | stopped` 且无更多字节 → `eof=true`。
6. **全文**：产品要求页面可看全部内容时，前端可先 `offset=0` 拉齐历史，再跟增量；或首屏用现有 download 拉全文，之后只跟 offset（需约定切换点）。

### A.2 后端备选：SSE

```http
GET /api/inference/tasks/{id}/logs/stream
```

`text/event-stream`，事件体可复用 `content` / `nextOffset` / `eof`。需处理网关超时、鉴权、断线重连。**非必须**；有 A.1 轮询即可达可用实时。

### A.3 前端改造点（对接 A.1 后）

| 模块 | 现状 → 目标 |
|------|-------------|
| `getInferenceTaskLogs(id, offset)` | 待新增于 `src/services/inference.ts` |
| `InferenceLogPanel` | 将「整文件 download + diff」替换为 offset 追加 `term.write` |
| Drawer 轮询 | 可保留状态轮询；日志轮询改为打 logs 接口，终态 + `eof` 停止 |

UX 保持：跟随滚动（上翻暂停）、复制、下载、空态提示。

### A.4 目标数据流

```
打开结果 Drawer
  → 刷新 GET /inference/tasks/{id}/result（进度/状态/logPath）
  → 轮询 GET /inference/tasks/{id}/logs?offset=N
  → xterm 追加 + sticky 滚动
  → 终态且 eof → 停止；仍可整文件下载
```

### A.5 过渡做法说明

当前前端的「反复 `downloadObject` 全文再 diff」属于 **无 A.1 时的过渡实现**。大日志浪费带宽，对象存储一致性可能导致 tail 不稳。**后端具备 A.1 + 运行中追写后，应切换为增量接口。**

## 三、方案 B：仅可视化（已覆盖，作能力分层说明）

目标：无需下载即可在页面阅读日志。前端主体已完成（且升级为 xterm + 全文）。

### B.1 后端

- **已用**：B.2.a — 复用 `GET /api/files/download`
- **可选增强**：`GET /api/inference/tasks/{id}/logs` 一次返回全文（按任务鉴权，免暴露 object 路径）

> 产品已明确要求 **全部展示**，不再推荐「默认只返回尾部 / 1～2MB 截断预览」作为主路径。若单文件极大影响性能，应优先：后端分页/offset、或前端性能优化（增大 scrollback 策略、虚拟化、下载兜底），并与产品单独约定，而不是静默截断。

### B.2 与当前前端、方案 A 的关系

| | 方案 B（可视） | 当前前端 | 方案 A（生产实时） |
|--|----------------|----------|-------------------|
| 在线看全文 | 是 | **已做**（xterm） | 是 |
| 运行中跟读 | 不要求 | 过渡轮询 download | offset / SSE |
| 后端新接口 | 可不改 | 未改 | **需要** |

## 六、结论

1. **前端现状**：xterm 内嵌终端 + **全文展示** + 运行中轮询下载追加；文档「现状」与检查清单已按此更新。
2. **后端下一步**：若要稳定、省流量的实时跟读，请实现 **A.1 增量接口** + worker **运行中追写**；前端再切数据源。

4. **产品「全部展示」**：以完整文件在终端可阅为准；极端大文件的性能策略需单独约定，避免再引入静默截断。
