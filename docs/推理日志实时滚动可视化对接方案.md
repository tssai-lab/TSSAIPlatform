# 推理日志实时滚动可视化 — 对接方案

给前后端对齐用的约定。当前推理工作台结果 Drawer 仅有「日志文件路径 + 下载日志」，无在线查看、无流式推送。本文约定两种能力：

1. **方案 A**：实时滚动可视化（运行中可跟读）
2. **方案 B**：仅可视化、不实时（任务结束后 / 有 `logPath` 后整文件在线查看）

前端入口：`src/pages/inference/workbench/index.tsx` 结果 Drawer。  
日志与结果可视化（`ResultVisual`）分离；系统操作审计日志（`/system/log`）不在此范围。

---

## 现状（基线）

| 项 | 现状 |
|----|------|
| UI | 展示 `logPath`，按钮「下载日志」 |
| 下载 | `logPath` → `objectNameFromMinioPath` → `GET /api/files/download?objectName=` → 另存为 `{taskId}.log` |
| 在线查看 | 无 |
| 实时流 | 无 SSE / WebSocket；任务表约 3s 轮询状态 |
| 结果 Drawer | 打开时拉一次 `GET /inference/tasks/{id}/result`，打开后不持续刷新 |

日志本体为纯文本（由 worker/脚本写入 MinIO）；前端目前不解析、不展示内容。

---

## 方案 A：实时滚动可视化（推荐完整能力）

与现有训练指标 / 任务表一致，优先 **增量轮询**；需要更低延迟时可再升级 SSE。

### A.1 后端：增量读接口（关键）

```http
GET /api/inference/tasks/{id}/logs?offset={byteOffset}&limit={maxBytes}
```

| 参数 | 说明 |
|------|------|
| `offset` | 已读字节游标，首次为 `0` |
| `limit` | 单次最大字节数，建议默认 64KB～256KB，并设上限 |

建议响应：

```json
{
  "content": "本次新增的纯文本（UTF-8）",
  "offset": 0,
  "nextOffset": 12345,
  "eof": false,
  "logPath": "minio://users/{uid}/inference-results/{taskId}/xxx.log",
  "status": "running"
}
```

| 字段 | 说明 |
|------|------|
| `content` | `[offset, nextOffset)` 区间的新增文本；无新增时为空串 |
| `offset` | 本次请求使用的起始游标（回显） |
| `nextOffset` | 下次请求应带的游标 |
| `eof` | 任务已终态且当前无更多可读字节时为 `true` |
| `logPath` | 可选；与任务元数据一致，便于前端展示 |
| `status` | 可选；便于前端决定是否继续轮询 |

行为约定：

1. **运行中可追写**：worker 将 stdout/stderr **追加**到同一日志对象（或本地文件再同步到 MinIO），保证 offset 语义成立。
2. **`logPath` 未就绪**：返回 `content=""`、`nextOffset=0`、`eof=false`（或明确 `ready: false`），HTTP 仍 200。
3. **鉴权**：按任务归属校验，与 `GET /inference/tasks/{id}` 一致。
4. **编码**：UTF-8；截断尽量落在字符边界，避免半截多字节字符。
5. **终态**：`success | failed | stopped` 且无更多字节 → `eof=true`。

### A.2 后端备选：SSE

若要求接近实时推送，可另提供：

```http
GET /api/inference/tasks/{id}/logs/stream
```

`text/event-stream`，事件体可复用增量片段字段（`content` / `nextOffset` / `eof`）。需处理网关超时、鉴权、断线重连（客户端带 last offset）。**一期不强制**；本仓库当前无 SSE 基础设施。

### A.3 前端

| 模块 | 职责 |
|------|------|
| `getInferenceTaskLogs(id, offset, limit?)` | `src/services/inference.ts` |
| `InferenceLogPanel` | 终端式面板：追加渲染、跟随滚动、工具栏 |
| Drawer 联动 | 打开后轮询任务态 + 日志；终态 + `eof` 停轮询 |

轮询建议（对齐现有约 3s 节奏，日志可用 2～3s）：

1. Drawer 打开且状态为 `queued | scheduled | running`（及尚有 `logPath` 但未 `eof`）时轮询增量。
2. 用 `nextOffset` 前进；`content` 为空则跳过无意义 setState。
3. **跟随滚动**：视口在底部附近则自动滚到底；用户上翻则暂停，提供「回到底部」。
4. 任务终态后再拉至 `eof`，然后停止。
5. **保留**现有「下载日志」。

UX 建议：

- 空态：「等待日志文件…」/「暂无新输出」
- 工具栏：复制全部、清空本地缓冲（仅 UI）、跟随开/关
- 可选：对含 `ERROR` / `WARN` 的行做简单高亮
- 超大日志：虚拟列表，或仅保留尾部 N 行（如 5000），避免 DOM 卡死

### A.4 数据流

```
打开结果 Drawer
  → 刷新 GET /inference/tasks/{id} 或 /result（进度/状态/logPath）
  → 轮询 GET /inference/tasks/{id}/logs?offset=N
  → LogViewer 追加 + sticky 滚动
  → 终态且 eof → 停止轮询；仍可整文件下载
```

### A.5 不推荐的过渡做法

仅前端反复 `downloadObject` 拉 MinIO **全文**再 diff：大日志浪费带宽，且对象存储一致性 / 缓存可能导致 tail 不可靠。仅允许作联调临时手段，生产应对齐 A.1。

## 方案 B：仅可视化、不实时

目标：用户无需下载即可在页面中阅读完整（或近似完整）日志；**不要求**运行中跟读。实现成本低于方案 A，可独立交付，也可作为 A 的降级形态。

### B.1 何时适用

- 后端暂不提供 offset / SSE
- 日志仅在任务结束后才落盘或才回写 `logPath`
- 产品只需「在线看一眼 + 仍可下载」

### B.2 后端约定（二选一）

**B.2.a 复用现有下载（前端改动即可）**

- 条件：任务存在 `logPath`，且 `GET /api/files/download?objectName=` 可返回纯文本
- 前端在 Drawer 打开且存在 `logPath` 时调用下载接口，将 Blob 以 `text()` 读入，渲染到 LogViewer
- **注意**：大文件会整包进内存；建议后端或网关对「预览」场景限制大小，或另提供尾部接口

**B.2.b 专用只读全文 / 尾部接口（更稳妥）**

```http
GET /api/inference/tasks/{id}/logs
```

或：

```http
GET /api/inference/tasks/{id}/logs?tailLines=2000
```

建议响应：

```json
{
  "content": "完整或尾部日志文本",
  "truncated": false,
  "logPath": "minio://...",
  "sizeBytes": 12345,
  "status": "success"
}
```

| 字段 | 说明 |
|------|------|
| `content` | 展示用文本 |
| `truncated` | 因超限只返回尾部时为 `true`，前端提示「仅显示末尾」 |
| `sizeBytes` | 可选；便于提示体积 |

行为约定：

1. 无 `logPath` 或文件未就绪：200 + 空 content，或 404（前后端需统一；建议 200 + 空，减少前端分支）。
2. 建议单次预览上限（如 1～2MB 或末尾 2000～5000 行），超出则 `truncated=true`，完整内容仍走「下载日志」。
3. 鉴权与任务详情一致。

### B.3 前端

同一 `InferenceLogPanel` 组件，交互简化：

| 行为 | 说明 |
|------|------|
| 触发时机 | Drawer 打开且 `logPath` 有值时拉取一次；或用户点击「查看日志」 |
| 刷新 | 不轮询；可选手动「刷新」按钮（再拉一次全文/尾部） |
| 滚动 | 默认滚到底或顶均可；无需 sticky 跟随逻辑 |
| 运行中 | 若尚无 `logPath`：提示「任务进行中，日志生成后可查看」；不自动跟读 |
| 下载 | 保留「下载日志」；`truncated` 时文案引导下载全文 |

布局建议：放在「下载日志」按钮下方、结构化结果 Collapse 上方（或与 Collapse 并列的「运行日志」折叠面板），深色 `<pre>` + `maxHeight` + `overflow: auto` 即可与现有「结构化结果」风格统一。

### B.4 数据流

```
打开结果 Drawer（任务已有 logPath，多为终态）
  → GET /files/download 或 GET /inference/tasks/{id}/logs
  → 文本填入 LogViewer（只读）
  → 用户可滚动阅读 / 复制 / 下载全文
```

### B.5 与方案 A 的关系

| | 方案 B | 方案 A |
|--|--------|--------|
| 后端 | 可不新接口，或只加一次读/tail | 必须增量 offset（或 SSE） |
| 运行中跟读 | 否 | 是 |
| 前端轮询 | 否（最多手动刷新） | 是（2～3s） |
| LogViewer | 可共用 | 共用 + 追加 / auto-scroll |
| 下载按钮 | 保留 | 保留 |

建议演进：**先落地 B（在线可视）→ 后端具备追写与 offset 后升级为 A（实时滚动）**，UI 组件一次建设、数据源切换即可。

## 对接检查清单

### 方案 B（仅可视化）

- [ ] 有 `logPath` 时可在页面内看到日志文本（全文或尾部）
- [ ] 超大日志有截断提示 + 仍可下载
- [ ] 无 `logPath` 时有明确空态
- [ ] 「下载日志」行为不变
- [ ] 与结果可视化、审计日志互不干扰

### 方案 A（实时滚动）

- [ ] `GET .../logs?offset=` 可用，游标语义正确
- [ ] 运行中日志可追写，增量连续无丢段、无乱序
- [ ] Drawer 打开后状态与日志同步刷新
- [ ] 跟随滚动 / 上翻暂停符合预期
- [ ] 终态 + `eof` 后停止轮询
- [ ] 保留下载；大日志不导致页面卡死

## 结论建议

1. **短期**：按 **方案 B** 在 Drawer 增加只读 LogViewer（优先 `logPath` + 现有下载转文本，或后端 `tail` 接口）。
2. **完整能力**：后端提供 **offset 增量接口** + worker 追写后，同一面板切 `mode=live`，即 **方案 A**。
3. SSE 作为可选增强，非一期必做。
