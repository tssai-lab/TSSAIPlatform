# 前端架构与功能扩展指南

核对日期：2026-09-10；生产代码基线 `523e5a0`。下文路径均相对本前端仓库。前后端总览另随工作区交接资料提供；本文件可独立随前端源码交付。

## 1. 先找到正确的一层

前端采用 React、Umi Max、TypeScript 和 Ant Design。主链路是“路由 → 页面 → 业务 services → 全局请求配置 → 后端”。部分资源监控代码仍为 JSX/JavaScript。

| 位置 | 负责什么 | 新功能什么时候改这里 |
| --- | --- | --- |
| `config/routes.ts` | 页面地址、菜单、页面入口与访问条件 | 新页面、菜单和路由参数 |
| `config/config.ts`、`config/defaultSettings.ts` | Umi 构建与应用配置、布局默认值 | 框架/布局配置，普通业务通常无需改 |
| `config/proxy.ts` | 开发环境 `/api/`、OpenAPI、MLflow 的代理 | 本地联调目标；生产代理看部署网关 |
| `src/app.tsx` | 当前用户、布局初始化、全局请求、登录失效与错误处理 | 全局行为；改动会影响很多业务 |
| `src/access.ts` | 菜单、页面和操作的前端访问条件 | 新角色入口或受限操作；后端仍须校验 |
| `src/pages/` | 各业务页面、页面内状态和交互 | 功能界面和页面专属流程 |
| `src/services/` | HTTP 请求、请求/响应类型、协议兼容和业务聚合 | 新接口、字段、请求参数及响应适配 |
| `src/components/` | 多页面复用的编辑器、预览、指标、状态等组件 | 确有多个调用方的共用 UI |
| `src/utils/` | 下载、错误识别、上传续传、状态显示等工具 | 可独立复用的规则；保留业务名称 |
| `src/typings.d.ts`、各 services 的类型文件 | 当前业务数据结构 | 新字段先补明确类型和响应校验 |
| `src/constants/`、`src/locales/`、`src/global.less` | 共用常量、语言和全局样式 | 跨页面的文案或外观 |
| `scripts/qa/`、源码旁的 `*.test.mjs` | 类型基线、契约和隔离页面保护 | 为新规则和故障边界补验证 |
| `public/`、`scripts/copy-swagger-ui.cjs` | 静态资源和 Swagger UI 资源复制 | 原始静态素材；生成资源通过构建更新 |
| `.github/workflows/`、`scripts/` | 检查、构建、运行和发布辅助 | 交付流程变化；先核对触发条件 |

`src/services/platform.ts` 是统一导出入口；`dataset.ts`、`code.ts`、`codeV2.ts`、`system.ts` 也保留兼容导出。新实现放对应职责模块，按需导出。部分页面直接使用具体服务，这是当前已有结构。

当前请求默认地址 `/api`、Bearer token 和错误兼容配置位于 `src/app.tsx`。不能凭惯例另造一个全局请求文件，造成两套登录或错误处理。

## 2. 所有业务页面的维护地图

以下页面路径相对 `src/pages/`，请求路径相对 `src/services/`。页面目录中的 `index.tsx` 通常是入口；详情采用 `[id].tsx` 等动态文件。

| 页面 / 地址 | 页面目录或文件 | 请求与规则入口 |
| --- | --- | --- |
| 首页 `/dashboard` | `dashboard/` | 模型、数据集、任务、资源监控服务聚合 |
| 登录/注册/找回/重置密码 `/user/*` | `user/login/`、`user/register/`、`user/forgot-password/`、`user/reset-password/` | `ant-design-pro/api.ts`、`ant-design-pro/login.ts` |
| 模型 `/model/list`、上传、详情 | `model/list/`、`model/upload/`、`model/detail/[id].tsx` | `model.ts`、`modelReadResponse.ts` |
| 数据集 `/dataset/list`、上传、详情 | `dataset/list/`、`dataset/upload/`、`dataset/detail/[id].tsx` | `dataset/`、`datasetV2.ts`、`datasetUploadResponse.ts` |
| 数据预览 `/dataset/preview/:versionId`、LeRobot 时序 | `dataset/preview/[versionId].tsx`、`dataset/lerobot-timeline/[versionId].tsx`、`dataset/components/` | `datasetPreview.ts`、`pointcloud.ts`、`datasetLeRobot.ts`、`datasetMultimodal.ts` |
| 训练代码 `/task/code/*` | `task/trainingCode/list/`、`upload/`、`detail/`、`pending/`、`adminAssets/` | `trainingCode/` |
| 创建训练 `/task/create` | `task/create/` | `task.ts`、`taskTypes.ts`、`trainingPlans.ts`、代码审批服务 |
| 训练列表、详情、对比 `/task/list`、`detail/:id`、`compare` | `task/list/`、`task/detail/`、`task/compare/` | `task.ts`、`mlflow.ts`、`mlflowMetricHistory.mjs` |
| 算力、节点详情 `/task/resourceMonitor/*` | `task/resourceMonitor/index.jsx`、`task/resourceMonitor/detail/[serverIp].jsx` | `resourceMonitor.ts` |
| 全局队列 `/task/queue` | `task/queue/` | `resourceMonitor.ts`；前端入口限超级管理员 |
| 推理 `/inference/workbench` | `inference/workbench/` | `inference.ts`；共用组件在 `src/components/inference/` |
| 用户、管理员 `/system/user`、`/system/admin` | `system/user/`、`system/admin/` | `system/user.ts`、`system/admin.ts` |
| 系统日志、本人日志 | `system/log/`、`account/my-logs/` | `system/log.ts`；本人和管理员查询范围不同 |
| 模型缓存、训练方案、系统配置 | `system/modelCache/`、`system/trainingPlans/`、`system/config/` | `system/modelCache.ts`、`system/trainingPlans.ts`、`system/config.ts`、`system/trainingCodeReviewPolicy.ts` |
| 用户手册、API 文档 | `user-manual/`、`api-doc/` | API 文档读取后端 OpenAPI；文档标签映射在页面目录 |
| 无权限、未知地址 | `403.tsx`、`404.tsx` | 路由末尾配置 |

路由地址 `/task/code` 对应磁盘目录 `task/trainingCode`；`/system/model-cache` 对应 `system/modelCache`。从路由配置定位页面，避免把 URL 当文件路径。

`ant-design-pro` 中的登录服务正在使用，正式接口为 `/user/login`、`/user/current-user` 等；不能把整个目录当脚手架示例删除。

## 3. 已拆开的职责，新功能沿着放

| 模块 | 职责边界 |
| --- | --- |
| `src/services/dataset/types.ts` | 数据集公开类型；区分资产 ID、版本 ID、上传会话和状态 |
| `src/services/dataset/assets.ts` | 资产/版本增删改及当前版本操作 |
| `src/services/dataset/catalog.ts` | 列表、详情、候选及兼容元数据聚合 |
| `src/services/dataset/uploads.ts` | 分片、续传、完成确认、对账与轮询 |
| `src/services/datasetV2.ts`、`src/services/datasetMultimodal.ts` | 工作区、样本、发布和多模态导入等现有 API |
| `src/services/trainingCode/v2OwnerApi.ts`、`v2AdminApi.ts`、`v2Types.ts` | 本人/管理员 V2 请求和类型 |
| `src/services/trainingCode/v2Mapping.ts`、`v2Content.ts`、`v2Tree.ts` | 响应兼容、内容解析、目录读取 |
| `src/services/trainingCode/assets.ts`、`inventory.ts`、`preview.ts` | 资产操作、列表聚合和预览 |
| `src/services/trainingCode/workspace.ts`、`adminWorkspace.ts`、`approval.ts` | 本人/管理员草稿、审批与完整训练准入 |
| `src/pages/task/create/useTrainingCreate.tsx` | 创建训练的总体流程；新增纯规则可抽取，由此编排 |
| `src/pages/task/create/TrainingCreateSteps.tsx` | 创建训练步骤展示 |
| `src/pages/task/detail/useExperimentVersions.ts` | 实验版本读取、加载和错误状态 |
| `src/pages/task/compare/useCompareData.ts`、`comparisonModel.tsx` | 对比读取与指标展示规则 |
| `src/pages/task/trainingCode/adminAssets/useAdminCodeBrowser.ts` | 管理员目录与文件读取，隔离迟到响应 |
| `src/pages/task/trainingCode/detail/useOwnerCodeDetailReads.tsx` | 本人代码详情读取 |

注意：详情请求失败要保留明确错误与只读重试；切换对象后旧请求不能覆盖新对象；网络超时不能当作草稿已被删除；完整训练准入不能用“代码 ZIP 校验通过”代替。新增功能必须保留这些边界。

## 4. 实施与验证

1. 先确定页面所属业务和现有服务。仅展示的功能通常止于前端；需要新保存字段、接口或规则时，先对齐后端 DTO、权限、状态和兼容方式。
2. 新 API 放相应服务模块，补类型与实际响应校验。页面组织加载、错误、重试和提交，不复制一套底层协议适配。
3. 新页面登记路由；受限入口登记 access。后端须独立拒绝越权，不能靠隐藏按钮代替权限。
4. 多步骤功能拆出职责明确的小模块，注释只解释编号、状态、顺序和限制等容易误解的地方。

生产代码改动后的基本检查（已有锁定依赖环境）：

```bash
npx --no-install max setup
npm run tsc
npm test -- --test-concurrency=1
npm run lint:governance
npm run build
```

按影响增加验证：数据集和训练参数见 `src/services/datasetContract.test.mjs`、`taskContract.test.mjs`；上传/错误边界见 `sixIssueReadUpload.test.mjs`、`threeBoundaryFailures.test.mjs`；交互用 `scripts/qa/read-errors-harness.mjs` 及对应检查脚本。它们有隔离替身，写操作和权限还需真实 API/存储/身份验证。详细要求见[代码维护索引](代码维护索引.md)与[接口契约与修改指南](接口契约与修改指南.md)。

`node_modules/`、`src/.umi/`、`dist/` 是依赖或生成目录；修改源文件后重新生成。前端类型 workflow 当前执行类型与治理 lint，尚未加入 `npm test`；不能仅凭该 workflow 绿灯判定新业务通过。
