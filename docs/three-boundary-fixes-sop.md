- 用户授权统一修复：训练准入盲目回退、主详情迟到覆盖、工作区读取失败误清草稿。本轮只改前端调用/展示，不改后端权限、数据库、任务调度或部署。

## A：项目事实

1. `CodeVersionService.trainingCheck` 校验代码包、方案启用及方案匹配；虽为 GET，内部会刷新验证证据。V2 `validate` 忽略请求体的 trainingProfile，只验证包，两者不等价。
2. 当前前端 catch 会执行 GET → POST validate → GET。前轮本地复现 403/429/500 仍调用 POST，甚至转换为 passed=true。
3. 模型/数据集主详情缺少请求顺序保护；前轮隔离回调复现 B 已加载，旧 A 又覆盖。详情写操作用路由 ID，显示和操作目标必须一致。
4. 工作区读取失败统一清空状态；已复现 timeout 清空且无提示。后端 `DATASET_WORKSPACE_NOT_FOUND` 同时用于非 DRAFT、删除、不存在和不可见，不能向用户断言删除。权限拒绝不可兜底成可编辑。

## B：默认方案及依据

- 继续使用现有完整 training-check 接口，不改公开签名。不提供不等价的 V2 回退，不自动再试；服务故障原样报错，接口不支持明确提示。此选择基于真实后端语义，不在前端复制方案/权限校验。
- 模型与数据集主请求采用现有序号/身份隔离方式；切换/卸载后旧成功、失败、finally、跳转均失效。当前读取未成功时不暴露旧详情写入口。相邻训练代码选择检查也隔离迟到结果。
- 工作区网络错误保留同一资产的上次工作区状态，明确显示错误及只读重试；恢复前不暴露陈旧编辑入口。只有明确业务“工作区不可用”或访问拒绝才清理可操作的本地工作区引用，不执行服务器删除/放弃。裸 404 不当作业务不存在。

## C：边界

无新增业务决策。旧接口正常成功/明确不通过、后端所有权/审批及训练最终校验保留。未知错误保守阻止操作；不声称自动重试能兼容没有完整准入接口的旧部署。改权限、接口语义或数据库须另行决策。

## 反向审查与假设影响

- 对照后端两个检查入口，确认 V2 包校验不等价。无完整准入接口的旧部署会明确报错，不能假装兼容；正常完整接口与后端授权不变。
- 补齐同资产 versionId 切换：旧查询参数的成功、失败及旧刷新回调同样失效，新增两页回归。
- 补齐详情暂缺 workspaceId：核实同资产已知工作区，不因元数据暂缺直接解除错误；工作区引用记录 datasetId，不拿其它资产的工作区补查。
- 暂时故障保留的是父组件已知工作区引用，**不承诺保住子面板尚未保存的所有输入**；服务器草稿不被这次读取删除。隐藏错误期间的旧编辑入口是保守措施，不新增后端权限。
- 不存在/非 DRAFT/不可见共用业务错误码，提示不直接断言删除。清理仅限本地编辑引用，不调用放弃或删除接口。
- 没有扩大架构重构、修改数据库或删测试。后端本轮无修改、未重新跑后端测试，也未连接内外网运行服务。

## 测试过程问题（不冒充产品缺陷）

- 初次 Node 执行被本地进程沙箱 EPERM 阻止，按授权重跑后取得真实失败证据。
- 一个并发用例未可靠等到请求开始就拒绝 Promise，导致测试结束后异步异常；改用显式请求开始信号，产品逻辑未为迎合测试改动。
- 浏览器夹具首次漏导出 previewModelCode，补齐依赖后成功；本地会话中断后改为记录 PID 的隐藏进程，未涉及远端服务。
