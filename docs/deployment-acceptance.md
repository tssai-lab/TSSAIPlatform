## 3. 启动与账号

- [ ] 从 `demo` 分支拉取，根目录存在 `frontend`、`backend`、`server`、`deploy`、`docs`。
- [ ] 已设置数据库与对象存储密码，确认它们不是网页登录密码。
- [ ] 执行 `docker compose -f deploy/compose.yml config --quiet` 无报错。
- [ ] `up -d --build` 成功，六个服务正常运行，后端日志没有数据库迁移、连接失败等异常。
- [ ] 打开登录页及项目页，地址跳转没有丢失访问端口，页面样式与校徽可加载。
- [ ] 全新数据库启动时执行了 `01-users.sql` 和 `02-demo-accounts.sql`，无需账号工具。
- [ ] 按指南重复执行默认账号 SQL，已有同名账号没有被修改或重复创建。
- [ ] 如更新既有服务器账号，备份数据库后按指南仅更新 `admin01`、`user01`；确认更新恰好两行、角色分别为 ID 2 / 3，且两账号均能用 `123456` 登录。
- [ ] 两个账号的角色符合文档；普通用户不能使用超级管理员的账号管理能力。
- [ ] 错误密码无法登录；退出后访问需要登录的页面会要求登录。
- [ ] 用户名注册可用，新用户为普通用户；不依赖短信服务。

只读健康检查：

curl -fsS http://127.0.0.1:8014/healthz
curl -fsS http://127.0.0.1:8014/label-api/health

## 5. 图像项目

准备含少量有效 PNG/JPG 的 ZIP，使用 `user01` 测试：

- [ ] 新建项目，输入与 ZIP 文件名不同的项目名，点击“选择压缩包”从本机选取文件。
- [ ] 文件卡片显示名称、大小；没有项目名称或没有文件时不能创建。
- [ ] 上传进度可见，最终状态为“可以标注”；项目名称与原文件名分别展示。
- [ ] 进入项目能看到图片与文件列表，正常图片可添加整图分类。
- [ ] 画矩形框、选择标签、点击应用，标签显示在对应标注记录中。
- [ ] 再次选中已有框，修改标签后仍是原来的框，不额外增加一个框。
- [ ] 保存后刷新或重新登录，框的位置、标签、备注和完成状态保持一致。
- [ ] 导出的 JSON 包含正确的文件名、标注和完成状态。

## 6. 时序项目

准备含数值 CSV 或 TEP DAT 的压缩包：

- [ ] 新建独立项目，不把时序数据并入刚才的图像项目。
- [ ] 曲线可显示，通道切换有效。
- [ ] 拖选区间及输入采样点编号均可设置标注范围。
- [ ] 设置状态、故障类别、涉及通道和备注后保存。
- [ ] 刷新、重新登录后数据和标注仍在，导出与界面记录一致。
- [ ] 切换分页前保存；已保存的前一页内容在返回时仍可读取。

## 7. 异常、隔离与持久化

- [ ] 服务器维护前备份标注服务数据卷；按项目名称 `项目上传部署验证`、上传文件名 `deployment-check.csv` 核对两条测试项目的 ID 后，仅删除这两条记录及其对应文件。
- [ ] 清理后确认两条测试项目不再显示，其他用户项目仍可访问；未删除数据库卷或其他项目数据。
- [ ] 暂停上传后，选择同一个原文件可继续；选错文件有错误提示。
- [ ] 无效或损坏的压缩包会报错，不会一直显示成功或可标注。
- [ ] 超过容量、文件数或时序长度限制时，显示明确错误。
- [ ] 用第二个账号登录，看不到第一个账号的标注项目；直接访问第一个账号的项目地址也不能读取数据。
- [ ] 两个页面修改同一条标注，旧版本保存时出现冲突提示，不静默覆盖新结果。
- [ ] 保存后执行 `docker compose -f deploy/compose.yml restart`，服务恢复后账号、项目、文件和标注仍存在。
- [ ] 备份流程同时涵盖 PostgreSQL、对象存储及标注 `/data` 卷。标注 JSON 导出不当作完整数据备份。

重启测试前先保存标注并等待上传、解包完成。不要使用删除数据卷的命令做“重启验证”。

## 8. 可重复执行的源码验证

安装前端依赖并完成 Umi setup 后，在仓库根目录执行：

```bash
npm --prefix frontend run tsc
npm --prefix frontend run build
node tests/data.cjs
node tests/archive.cjs
node tests/edit-mark.cjs
(cd backend && ./mvnw -Dtest=DemoSeedAccountsTest test)
(cd server && python3 -m unittest test_app.py)
(cd backend && ./mvnw -DskipTests package)
```

默认账号测试只读取 SQL 并验证角色和 BCrypt 密码，不调用 Docker、修改真实账号或连接现有服务器；标注接口测试仅使用临时目录及本机临时端口。测试数据不含用户提供的真实数据集。
