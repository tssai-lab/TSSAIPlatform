# 推理结果可视化 — 后端对接清单

给后端看的最短约定。前端按此对接；细节实现以后端为准。

---

## 一、建议对齐（优先）

### 1. `result` 增加 `view`（建议）

任务成功后的结构化结果里建议增加：

```json
"view": "image_detection" | "image_classification" | "table_classification" | ...
```

有 `view` 时前端直接按类型渲染；没有时前端会按字段探测（兼容现有结果）。

一期建议覆盖：

| view | 何时写 |
|------|--------|
| `image_detection` | 有检测框（YOLO 等） |
| `image_classification` | 图像分类（MobileNet 等） |
| `table_classification` | 表格/融合二分类等 |

完整枚举见文末。

### 2. 图片给「前端能加载」的地址

**不要只给** `/workspace/job/...`（浏览器打不开）。

建议给相对任务 `outputPath` 的路径，例如：

```json
"annotatedImage": "annotated/xxx.jpg"
"media": { "path": "preview/0.jpg" }
```

`outputPath` 示例：`minio://users/1/inference-results/{taskId}/outputs/`

| 类型 | 建议的图字段 |
|------|----------------|
| 检测 | `annotatedImage` 或 `annotated.path`（文件在 outputs 下） |
| 分类若要配图 | 每条样本 `media.path`（或 `objectName` / 预签名 `url`） |
| 表格融合 | 一般不需要图 |

### 3. `result` 保持「摘要 + 短预览」

- 指标、分布、预览列表（几十条内）放在 `result`
- 不要把全量预测塞进 `result`
- 全量继续写文件即可（如 `predictions.csv` / `predictions.jsonl`）

前端：页面看预览；整包用已有「下载结果」（`result.json`）。

## 二、文件 / 图片怎么下载

### 现在前端在用什么

推理「下载结果 / 日志 / 标注图预览」当前走的是：

```http
GET /api/files/download?objectName={完整对象路径}
```

例如把 `outputPath` 与 `annotated/xxx.jpg` 拼成：

`users/1/inference-results/{taskId}/outputs/annotated/xxx.jpg`

### 若不想对前端暴露 MinIO 对象路径

可由后端新建推理媒体接口（按任务鉴权，内部读存储），例如：

```http
GET /api/inference/tasks/{id}/media?path=annotated/xxx.jpg
```

或返回短时预签名 URL。前端再改为调该接口。  
**未提供前，前端继续用现有 `/api/files/download`。**

## 三、建议新增（要做页面「全量」可视化时）

```http
GET /api/inference/tasks/{id}/predictions?page=1&pageSize=50
```

返回：`{ total, page, pageSize, list: [...] }`  
`list` 与对应类型字段一致；需要配图的行带上可加载的图片字段。

没有这个接口前，前端**只展示预览**，不做全量表。

---

## 四、已有、前端在用的接口

| 接口 | 用途 |
|------|------|
| `GET /api/inference/tasks/{id}/result` | 返回 `result`、`outputPath` |
| `GET /api/files/download?objectName=` | 当前下载产物图 / result.json / 日志 |

## 五、三类结果建议字段（对照）

**检测 `image_detection`**

- `view`（建议）
- `totalDetections` / `imageCount`
- `images[]`：`detections[].bbox|className|confidence`，`annotatedImage`

**分类 `image_classification`**

- `view`（建议）
- `top1Accuracy`、`labelCounts`、`predictionCounts`（可选）
- `predictionsPreview[]`：`label`、`prediction`、`confidence`、`correct`、`topKRecords`
- 配图：优先使用下述 `inputPreview`；旧脚本仍兼容 `media.path`（相对 outputs）

**推理原始输入预览 `inputPreview`**

每条预览行可带一个统一的原始输入描述，路径必须相对当前任务的
`outputPath`，不能填写 `/workspace`、其他用户对象路径或完整 URL：

```json
{ "kind": "image", "name": "sample-1.jpg", "path": "previews/images/0.jpg" }
{ "kind": "text", "name": "原始文本 #1", "summary": "前160字…", "path": "previews/text/0.txt", "truncated": true }
{ "kind": "file", "name": "sample.pcd", "path": "previews/files/0.pcd" }
```

- 图片脚本只写小尺寸预览图，不重复保存整套原始数据集。
- 短文本可以直接放 `inputPreview.text`；长文本写入任务输出的
  `previews/text/`，结果 JSON 只放摘要和相对路径。
- 预览数量必须有上限；正式验收脚本当前最多生成 50 条。
- 文件类型默认只提供下载，不在浏览器里猜测并执行内容。

**表格 `table_classification`**

- `view`（建议）
- `accuracy`、`rowCount`、`positiveCount`、`negativeCount` 等
- `preview[]`：`probability`、`prediction`、`label`、`correct`

准确率类数字建议用 **0~1**。

## 六、对齐检查（建议）

- [ ] 新任务 `result` 尽量带 `view`
- [ ] 检测标注图相对 `outputPath`，当前 files 接口能下（或已提供 media 接口）
- [ ] 分类若要约配图：样本带可加载路径，不是只有 workspace
- [ ] 原始输入仅引用当前任务 `outputPath` 下的相对路径，且预览数量、尺寸有上限
- [ ] `result` 只有预览，不全量数组
- [ ] （可选）提供 `/predictions` 分页后再做全量页面
- [ ] （可选）提供 `/media` 或预签名，避免前端拼 objectName
