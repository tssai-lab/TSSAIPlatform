# 推理日志可视化与实时滚动 — 对接方案

给前后端对齐用。日志与结果可视化（`ResultVisual`）分离；系统操作审计日志（`/system/log`）不在此范围。

前端入口：`src/pages/inference/workbench/index.tsx` 结果 Drawer →「运行日志」。

---

## 一、本期已做：整文件可视化（不是正式实时滚动）

**目标**：把原先只能下载才能看的推理日志，在页面内嵌终端中**完整展示**。

| 项 | 约定 / 实现 |
|----|-------------|
| UI | xterm.js 内嵌终端；保留「下载日志 / 刷新 / 复制」 |
| 内容 | **展示日志文件全文**（产品要求全部展示） |
| 数据 | `logPath` → `objectNameFromMinioPath` → `GET /api/files/download?objectName=` → 写入终端 |
| 后端 | **不新增接口**，复用现有下载 |
| 范围说明 | 这是「在线看完整日志」，**不等于**「运行中日志实时往外蹦」 |

相关代码：

| 路径 | 说明 |
|------|------|
| `src/components/inference/InferenceLogPanel/index.tsx` | xterm 终端面板 |
| `src/pages/inference/workbench/index.tsx` | 结果 Drawer 挂载 |
| `src/services/files.ts` | `downloadObject` |
| `package.json` | `@xterm/xterm`、`@xterm/addon-fit` |

### 本期验收

- [x] 有 `logPath` 时，结果页终端可查看**完整**日志内容
- [x] 无 `logPath` 时有空态提示
- [x] 「下载日志」行为保留
- [x] 与结果可视化、审计日志互不干扰

> 说明：前端可能在任务未结束时定时再拉一次整文件，以便文件若已变长则更新终端。这只是无增量接口时的辅助，**不能当作正式的「日志实时滚动可视化」交付**；日志若在任务结束才一次性写入，运行中仍不会持续出字。

## 二、后续要做：日志实时滚动可视化

**目标**：任务**运行中**，终端里日志持续「往外蹦」，并自动滚到最新一行（live tail）。

这需要后端具备能力后，前端再切换数据源；**仅靠整文件下载无法作为正式方案。**

### 2.1 后端必须做（缺一不可）

**（1）运行中追写日志**

- worker 将 stdout/stderr **持续追加**到同一日志文件 / MinIO 对象  
- 若仍是任务结束后才一次性落盘，前端无法在运行中拿到新内容

**（2）增量读接口（推荐）**

```http
GET /api/inference/tasks/{id}/logs?offset={byteOffset}&limit={maxBytes}
```

| 参数 | 说明 |
|------|------|
| `offset` | 已读字节游标，首次 `0` |
| `limit` | 单次最大字节，建议默认 64KB～256KB |

建议响应：

```json
{
  "content": "本次新增的纯文本（UTF-8）",
  "offset": 0,
  "nextOffset": 12345,
  "eof": false,
  "logPath": "minio://users/{uid}/inference-results/{taskId}/xxx.log",
  "status": "running"
}
```

| 字段 | 说明 |
|------|------|
| `content` | 本次新增文本；无新增为空串 |
| `nextOffset` | 下次请求携带的游标 |
| `eof` | 终态且无更多字节时为 `true` |

其它约定：

- `logPath` 未就绪：200 + 空 content、`nextOffset=0`
- 鉴权与任务详情一致
- UTF-8；尽量避免截断半个多字节字符
- 终态：`success | failed | stopped` 且无更多字节 → `eof=true`

**（3）SSE（可选，非必须）**

```http
GET /api/inference/tasks/{id}/logs/stream
```

有增量轮询即可；SSE 用于更低延迟推送。

### 2.2 前端后续改造

在现有 xterm 面板上改数据源即可：

| 步骤 | 内容 |
|------|------|
| 1 | `src/services/inference.ts` 增加 `getInferenceTaskLogs(id, offset)` |
| 2 | `InferenceLogPanel`：用 offset 增量 `term.write`，**去掉**整文件轮询 diff |
| 3 | 运行中轮询 logs 接口（约 2～3s）；终态 + `eof` 停止 |
| 4 | 保持贴底跟随滚动、复制、下载、空态 |

目标数据流：

```
打开结果 Drawer
  → 刷新任务状态 / logPath
  → 轮询 GET .../logs?offset=N（或 SSE）
  → xterm 追加新内容并滚到底
  → 终态 + eof → 停止；完整文件仍可下载
```

### 2.3 后续验收（实时滚动）

- [ ] 运行中日志可持续追写
- [ ] `GET .../logs?offset=` 游标正确、无丢段乱序
- [ ] 前端已切换增量接口，不再靠整文件轮询冒充实时
- [ ] 终端运行中持续追加，跟随滚动正常
- [ ] 终态 + `eof` 后停止轮询
- [ ] 「下载日志」仍可用
- [ ] （可选）SSE

## 五、结论

1. **本期**：拿到整文件，在 xterm 中**完整可视化**——已完成。  
2. **后续「日志实时滚动可视化」**：后端先做 **运行中追写 + `logs?offset=`（或 SSE）**，前端再改为增量追加；不要把整文件轮询当成正式实时方案。  
3. 超大日志若影响性能，再单独约定优化（虚拟化 / 分页等），不以静默截断替代「全部展示」。
