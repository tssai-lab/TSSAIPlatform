# 接口契约与修改指南

从[代码维护索引](代码维护索引.md)找功能，再看本文件确认字段和边界。这里整理当前实现，不新增业务规则；后端 DTO、控制器、校验和测试共同决定接口行为。

## 数据集：先分清三个编号

| 字段 | 含义 | 修改入口 |
| --- | --- | --- |
| assetId / datasetId | 数据集资产编号；具体接口保留各自字段名 | `src/services/dataset/assets.ts` |
| versionId / datasetVersionId | 版本编号；训练必须引用具体版本 | `src/services/dataset/types.ts`、`assets.ts` |
| uploadId / workspaceId | 上传会话 / 编辑草稿，不能当成已发布版本 | `uploads.ts`、`datasetUploadResponse.ts`、`datasetV2.ts` |

`src/services/dataset.ts` 保留原公开入口，页面无需改导入。实现只向下依赖 `dataset/` 的职责模块；回执整理只从 `dataset/types.ts` 引用类型。

- **上传**：先调用 V2 初始化、缺片上传、完成接口。只有明确端点不支持才走已有旧接口兼容；超时、权限或服务异常不能触发另一轮写入。完成请求状态不确定时，按现有规则查询会话对账。
- **状态**：`COMPLETED` 表示上传阶段完成。导入是否完成、草稿是否发布、版本是否可用于训练，分别读取各自状态。兼容上传结果中的 `datasetVersionId` 可能承接 `workspaceId`，必须按调用场景核实，不能据此直接创建训练。
- **详情**：`catalog.ts` 用资产、版本接口组装主体，再从旧列表补工作区等元数据；这段补充读取的历史降级行为仍保留。工作区暂时故障与不可访问由 `utils/datasetWorkspaceRead.ts` 区分，错误重试不能偷偷创建或放弃草稿。
- **版本更新**：`version` 仍按原实现映射成后端 `versionLabel`，不改传入对象。路径中的编号始终按原规则编码。

后端核对入口（后端仓库内）：`backend/src/main/java/com/tss/platform/controller/v2/V2DatasetUploadController.java`、`DatasetUploadController.java`、`DatasetAssetCrudController.java`、`DatasetVersionCrudController.java`（后三者在 `controller/`）；状态和补偿看 `service/DatasetUploadService.java`、`ImportJobService.java`、`DatasetWorkspaceFileUploadService.java`。

## 训练：创建和续训共用字段，必填条件不同

| 契约 | 规则 | 后端 DTO |
| --- | --- | --- |
| `CreateTaskRequest` | 当前前端要求 `datasetVersionId`；`trainingProfile` 保留旧方案别名 | `CreateTrainingExperimentRequest` |
| `CreateExperimentVersionRequest` | 未提供字段由后端按当前继承规则处理；前端不填默认版本 | `CreateExperimentVersionRequest` |
| `TrainingResourceRequest` | CPU 是核数，内存和显存字段用 MiB；硬件用 `hardwareTargetId` | `TrainingResourceRequest` |

具名类型集中在 `src/services/taskTypes.ts`；`task.ts` 只封装请求，错误交给页面处理，不自动重放创建、停止、删除或发布。

`baseModelVersionId` 是后端落到 `modelVersionId` 的 API 别名。`hyperParams` 保留现有对象/字符串能力，不因为补类型就转换值、删掉零值或新增校验。Java DTO 还兼容 `params`，本轮不擅自扩展前端字段。

训练创建页面的选择、准入、审核、资源校验和提交顺序仍在 `src/pages/task/create/useTrainingCreate.tsx`。`trainingResourcePresentation.mjs` 负责资源请求换算；GPU 显存预算是运行框架的软限制，不能当成 Kubernetes 已提供显存硬隔离。

## 审核和训练准入分开维护

`src/services/trainingCode/approval.ts` 的审批仍保留原权限、审核证据和版本并发校验。`checkCodeVersionForTraining` 必须读取完整 `training-check`：代码包通过不代表方案启用、匹配或可训练。该 GET 会刷新校验证据，也不能当普通查询自动重试。

请求失败不能包装成空列表或成功；业务失败回执按既有契约处理。`unknown` 只要求使用前判断类型，不代表服务端回执已经经过运行时校验。

## 一次功能改动怎么验收

1. 在维护索引找到入口，写清新字段或状态会影响上传、发布、训练中的哪一步。
2. 先补能观察业务结果的边界用例；请求契约测试替换网络，执行真实服务函数，不复制实现。
3. 跑前端完整保护门：`npm run postinstall`、`npm run tsc`、`npm test`、`npm run lint:governance`、`npm run build`。
4. 改数据库、对象存储、权限或补偿时，在独立 Docker 上跑后端 `backend/scripts/qa/run-container-integration.sh`；10 套件缺报告、跳过或失败均不放行，详见后端维护索引。
5. 改页面交互再补对应页面/控件回归。发布前另做真实登录、上传—草稿—发布—训练—结果读取；隔离页面和容器测试不替代这一步。

现有仓库仍有历史宽类型和较长编排模块。新增服务不允许引入 `any`，已有逐文件数量只能减少；不要为了改一处功能顺手清空全部旧告警。
