# AI训练平台 — 前端部署文档

## 一、项目概述

| 项目名称 | AI训练平台（前端） |
|----------|-------------------|
| 技术栈 | React 19 + Ant Design Pro 6 + UMI 4 |
| 路由模式 | Hash 模式 |
| 构建工具 | Mako（UMI 内置 Rust 打包器） |
| 默认端口 | 8000 |

---

## 二、运行环境要求

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| Node.js | ≥ 20.0.0 | 推荐使用 v20 LTS |
| npm | 随 Node.js 自带 | 版本 ≥ 10.x |
| 操作系统 | Linux（推荐 CentOS 7+ / Ubuntu 20.04+） | 也支持 Windows Server |

> **注意**：Node.js 仅用于**构建阶段**和服务端代理脚本。最终交付物为纯静态文件（HTML/JS/CSS），不依赖 Node.js 运行时（使用方案二部署时）。

## 三、构建步骤

### 3.1 获取源码

```bash
git clone <仓库地址>
cd myproject-frontend-dev
git checkout frontend-dev
```

### 3.2 安装依赖

```bash
npm install
```

### 3.3 构建生产产物

```bash
npm run build
```

构建完成后，产物位于 `dist/` 目录，目录结构如下：

```
dist/
├── index.html          # 入口页面
├── umi.xxxxxxxx.js     # 主业务代码
├── vendors_*.js        # 第三方依赖
├── *.css               # 样式文件
├── scripts/            # 静态脚本（如 loading.js）
└── 各路由页面/
    ├── dashboard/index.html
    ├── task/index.html
    ├── api-doc/index.html
    └── ...
```

### 3.4 环境变量说明

构建时可通过以下环境变量控制行为：

| 变量名 | 默认值 | 说明 |
|--------|-------|------|
| `REACT_APP_ENV` | `prod` | 环境标识，决定代理配置选用 |
| `REACT_APP_HISTORY_MODE` | `hash` | 路由模式，`hash` 或 `browser` |
| `HOST` | `0.0.0.0` | 服务绑定地址 |
| `PORT` | `8000` | 服务端口 |
| `BACKEND_PROXY_TARGET` | `http://47.114.84.133:8080` | 后端 API 地址（启动脚本用） |
| `MLFLOW_PROXY_TARGET` | `http://127.0.0.1:5000` | MLflow 服务地址（启动脚本用） |

## 四、部署方式

提供两种部署方案，任选其一。

### 方案一：Express 一体化部署（推荐，最简单）

本方案使用项目自带的 Express 脚本，同时提供**静态文件服务**和**API 反向代理**，无需额外安装 nginx。

#### 4.1.1 在服务器上执行

```bash
# 安装依赖
npm install

# 构建 + 启动服务
npm run serve:prod
```

服务启动后输出：

```
Frontend is available at http://0.0.0.0:8000
Proxy /api -> http://47.114.84.133:8080
Proxy /mlflow-api -> http://127.0.0.1:5000/ajax-api
```

#### 4.1.2 代理规则

| 浏览器请求路径 | 转发目标 | 说明 |
|---------------|---------|------|
| `/api/*` | 后端 `:8080` | 平台业务 API |
| `/mlflow-api/*` | MLflow `:5000`，路径改写为 `/ajax-api/*` | 训练指标数据 |
| `/v3/api-docs` | 后端 `:8080` | OpenAPI 文档 |

#### 4.1.3 自定义后端地址

如果后端不在本机，通过环境变量指定：

```bash
BACKEND_PROXY_TARGET=http://192.168.1.100:8080 \
MLFLOW_PROXY_TARGET=http://192.168.1.100:5000 \
npm run serve:prod
```

#### 4.1.4 使用 PM2 守护进程（生产推荐）

```bash
# 安装 PM2（仅首次）
npm install -g pm2

# 启动
pm2 start scripts/serve-dist.cjs --name ai-platform-frontend

# 设置开机自启
pm2 save
pm2 startup
```

常用 PM2 命令：

```bash
pm2 status              # 查看状态
pm2 restart ai-platform-frontend  # 重启
pm2 logs ai-platform-frontend     # 查看日志
pm2 stop ai-platform-frontend     # 停止
```

### 方案二：Nginx 静态部署

如果已有 nginx 环境或需要与其他服务共用 80 端口，使用此方案。

#### 4.2.1 上传静态文件

将 `dist/` 目录下所有文件上传至服务器，例如：

```bash
scp -r dist/* user@47.114.84.133:/var/www/ai-platform/
```

#### 4.2.2 Nginx 配置文件

在 `/etc/nginx/conf.d/ai-platform.conf`（CentOS）或 `/etc/nginx/sites-available/ai-platform.conf`（Ubuntu）中写入：

```nginx
server {
    listen 80;
    server_name 47.114.84.133;   # 修改为实际域名或 IP

    root /var/www/ai-platform;
    index index.html;

    # ========== API 代理 ==========

    # 平台后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # MLflow 服务（路径改写：/mlflow-api → /ajax-api）
    location /mlflow-api/ {
        rewrite ^/mlflow-api/(.*) /ajax-api/$1 break;
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # OpenAPI 文档
    location /v3/api-docs {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ========== 静态文件 ==========

    # SPA 路由回退：所有非文件路径返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|svg|ico|woff|woff2|ttf)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

#### 4.2.3 重载 Nginx

```bash
nginx -t                    # 检查配置语法
systemctl reload nginx      # 重载生效
```

## 五、验证部署

### 5.1 页面访问

浏览器打开 `http://<服务器IP>:8000`（方案一）或 `http://<服务器IP>`（方案二），应看到登录页。

### 5.2 API 连通性

在浏览器控制台（F12 → Network）中：
- 输入正确用户名/密码登录，应正常跳转到 Dashboard
- 访问「OpenAPI 文档」→「在线调试」页签，应能加载 Swagger UI 并显示接口列表

### 5.3 代理验证

直接访问以下地址确认代理生效：

```
# 后端 API（返回 JSON）
http://<服务器IP>:8000/api/xxx

# OpenAPI 文档（返回 JSON）
http://<服务器IP>:8000/v3/api-docs
```

## 六、常见问题

### Q1：构建报错 `node: not found` 或版本过低

Node.js 版本需 ≥ 20.0.0，使用以下命令检查：

```bash
node --version
```

版本过低时，建议使用 nvm 管理：

```bash
# 安装 nvm（仅首次）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash

# 安装并使用 Node.js 20
nvm install 20
nvm use 20
```

### Q2：页面刷新后 404

确认路由模式为 **Hash 模式**（`REACT_APP_HISTORY_MODE=hash`）。如果使用 Browser 模式，需确保 nginx 配置了 `try_files $uri /index.html`。

### Q3：OpenAPI 文档页加载失败

检查浏览器控制台报错：
- 若报 `Failed to fetch`：确认 `/v3/api-docs` 代理配置正确，且后端服务正常运行
- 若报 `SwaggerUIBundle is not defined`：检查 `dist/swagger-ui/` 目录下是否存在 `swagger-ui-bundle.js`，确认 `prebuild` 脚本已正确执行

### Q4：登录成功但无法获取数据

检查 `/api/` 代理是否生效，确认后端服务 `8080` 端口可达：

```bash
curl http://127.0.0.1:8080/api/xxx
```

### Q5：端口被占用

修改启动端口：

```bash
PORT=9000 npm run serve:prod
```

## 七、附录

### 7.1 项目脚本速查

| 命令 | 用途 |
|------|------|
| `npm install` | 安装依赖 |
| `npm run build` | 生产构建（产物在 `dist/`） |

### 7.2 关键文件说明

| 文件/目录 | 说明 |
|-----------|------|
| `dist/` | 构建产物，部署时上传此目录内容 |
| `scripts/serve-dist.cjs` | Express 一体化服务脚本（方案一核心） |
| `config/proxy.ts` | 开发环境代理配置（生产不用） |
| `config/config.ts` | UMI 框架配置（路由、构建参数等） |

| `package.json` | 项目依赖与脚本定义 |

前端正常运行依赖以下后端服务：

| 服务 | 默认地址 | 用途 |
|------|---------|------|

| MLflow 服务 | `http://127.0.0.1:5000` | 训练任务指标数据 |
