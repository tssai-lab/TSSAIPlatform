# NLP CPU/单卡 GPU 验收操作步骤

## 一、准备条件

1. 平台前后端、数据库、对象存储和目标计算节点正常；
2. CPU 节点带有标签 `tss.ai/node-pool=cpu`；GPU 节点带有标签 `tss.ai/accelerator=nvidia`；
3. 目标节点已有对应的 NLP 训练镜像；GPU 方案还需 NVIDIA 驱动、设备插件和 `nvidia` RuntimeClass 正常；
4. 超级管理员可以导入训练方案并审批训练代码；
5. 单个任务建议至少分配 4 核 CPU、8 GiB 内存和 12 GiB 临时磁盘上限。

## 二、操作步骤

1. CPU 训练导入 `minirbt_text_classification-v1.yaml`；单卡 GPU 训练导入 `minirbt_text_classification_gpu-v1.yaml`；若已有同版本方案，先核对 SHA-256；
2. 上传 `minirbt-h288-base.zip`，资产大类选择 `NLP`；
3. 上传 `massive-zhcn-intent-dataset.zip`，资产大类选择 `NLP`；
4. 上传 `minirbt-training-code.zip`，入口文件填写 `train.py`，由超级管理员审批；
5. 新建训练任务，选择 CPU 或“MiniRBT 中文文本分类（单卡 GPU）”，再选择上述模型、数据集和代码；
6. GPU 小型验收使用：`epochs=1`、`batchSize=8`、`lr=0.0001`、`maxSeqLength=64`；CPU 验收可将 `epochs` 调为 2；
7. 启动训练，确认任务成功，并至少能看到 loss、accuracy、precision、recall、F1；
8. 下载训练结果模型和预测文件；
9. 上传 `minirbt-inference-script.zip`，入口文件填写 `infer.py`，使用训练生成的模型发起推理；
10. 确认结果包含原始文本、预测标签和置信度。

## 三、通过标准

- 资产和训练方案能被平台接受；
- 训练任务在所选类型的计算节点实际运行并成功结束；
- GPU 任务必须报告 `device=cuda:0`、`visibleCudaDevices=1`，Job 必须申请 `nvidia.com/gpu=1` 并使用固定摘要镜像；
- 页面展示真实进度、日志和五项核心指标；
- 结果模型可以下载并用于一次推理；
- Job/Pod 清理后，已归档的日志、指标和结果仍可查看；
- 失败时页面显示真实原因并保留排查信息。

若要验证稳定性，应连续运行 3 次。上一轮成功后需等待配置的 Job TTL 真正清理完成，再发起下一轮；在当前 NVIDIA 设备插件实现中，已完成但尚未删除的 Pod 仍可能短暂保留 GPU 分配记录。
